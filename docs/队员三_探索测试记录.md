## 3. 报告可信度核验（三-2）— 状态说明

当前 `LLM_PROVIDER=mock`，报告为**模板假报告**，因此以下项**先挂起**，待接真模型后复测：

- ❌ 报告是否真引用对应论文（现为机械切分）
- ❌ 报告是否乱编具体结论（现为模板句）
- ⚠️ 是否有"局限/limitations"段 → **现在即判定"有"**（模板内确实带 limitations 段，但为模板文字，暂不作正式结论）

**模板报告结构（已读 `backend/llm/report.py`）**：
- `overview` 含【本地样例报告，未接入模型】提示，并写明"请在 .env 配置 LLM_API_KEY 并把 LLM_PROVIDER 改为 openai"。
- `themes` 固定 3 个主题名，`paper_ids` 为**机械切分**（`pid[:2]/pid[2:4]/pid[4:6]`），与内容无关。
- 有 `limitations` 段；无"编造具体结论"（全为模板句 + 【样例】前缀）→ 这点现在即可判"无乱编"。

> **待接真 LLM 后复测**：引用是否真对应、是否出现具体编造、局限段是否真实。

## 5. 可复现 Bug 单（三-3）

### BUG-01 【P1】中文主题检索结果严重不相关

- **现象**：输入"超快成像"等**未在翻译对照表内**的中文主题，返回的论文大量与主题无关（混入 `Rapid Diagnosis of Plantaris Tendon Rupture / 跖肌腱断裂诊断` 等完全不相关记录）。
- **复现步骤**：前端搜索框输入 `超快成像` → 点"生成报告" → 查看论文卡片。
- **预期**：返回与"超快成像"相关的论文。
- **实际**：混入无关记录，相关性差。
- **根因**（已读 `backend/llm/translate.py` + `backend/pipeline.py`）：
  1. `pipeline._run_research` 先 `resolve_keyword()` 做"中文→英文"翻译；
  2. 翻译只有两条路：① `KEYWORD_MAP` 硬编码对照表（约 30 词）；② 调大模型（要求 `llm_provider=="openai"` 且有 `llm_api_key`）；
  3. "超快成像"**不在对照表**，且当前 `LLM_PROVIDER=mock` 无 Key → 翻译失效 → `resolve()` 返回**原样中文**；
  4. 中文串直接丢给 Crossref → 中文查询乱匹配，捞回无关期刊记录。
  5. 代码自身注释即警告此风险（`translate.py` 开头：*"不翻译…会捞回一堆不相关的中文水刊"*）。
- **简易判据**：翻译成功时页面显示灰条"已按「xxx」检索"；**无此灰条 = 未翻译**（超快成像即无）。
- **修复建议**：① 配真 LLM Key（翻译生效）；② 扩充 `KEYWORD_MAP`；③ 增加国内论文源。
- **规避技巧**：表外主题可直接输**英文关键词**（如 `ultrafast imaging`），绕过中译英失真。
